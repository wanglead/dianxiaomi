# Windows 11 多平台订单临期预警助手设计

## 背景与目标

本项目已有 Chrome Manifest V3 浏览器插件和本地 FastAPI 系统雏形。本功能新增一个面向 Windows 11 的订单临期预警助手，由 Chrome 扩展与 .NET 8 Windows 托盘程序组成。

助手定时检查店小秘指定的四个订单页面和多个速卖通店铺的订单管理页面，读取订单的考核时间与剩余发货时间，统计临期和超时订单，并通过可独立关闭的 Windows 弹窗与声音提醒用户。

目标页面：

- 店小秘已付款：`https://www.dianxiaomi.com/web/order/paid?go=m100`
- 店小秘待审核：`https://www.dianxiaomi.com/web/order/approved?go=m101`
- 店小秘自营仓处理：`https://www.dianxiaomi.com/web/order/processed/self_warehouse?go=m10201`
- 店小秘已分配：`https://www.dianxiaomi.com/web/order/allocated/has?go=m10301`
- 速卖通订单管理：`https://csp.aliexpress.com/m_apps/order-manage/orderList?channelId=244176`

## 已确认决策

- 产品形态采用“Chrome 扩展 + .NET 8 Windows 托盘程序”。
- 浏览器固定支持 Google Chrome，Windows 目标版本为 Windows 11。
- 扩展读取登录后的订单页面；托盘程序负责账号管理、定时调度、统计、去重、通知和声音。
- 仅在用户设置的时段内检查，默认建议为 `08:00–22:00`，默认每 15 分钟检查一次。
- Chrome 未运行时自动启动；登录失效、验证码或二次验证出现时提示用户人工处理。
- 重复预警采用“状态变化时立即提醒，之后每 2 小时重复提醒”。
- 速卖通支持手动添加多个店铺。每个店铺使用独立 Chrome 登录配置，首次由用户手动登录，应用不保存账号密码。
- 店小秘和速卖通使用相同的两类时间规则；页面仅提供一种时间时，按可读取到的时间判断。

## 范围

### 第一版包含

- 检查店小秘四个固定订单页面。
- 添加、编辑、停用和删除多个速卖通店铺配置。
- 为每个速卖通店铺建立独立 Chrome 登录配置并复用登录会话。
- 自动启动 Chrome，打开目标页面并触发检查。
- 解析订单号、平台、店铺、订单状态、考核时间和剩余发货时间。
- 自动翻页或加载完整订单列表，在一次扫描中合并结果。
- 统计 24 小时内临期、2 小时内紧急和已超时订单。
- Windows 弹窗、声音、稍后提醒、点击打开对应订单页面。
- 设置监控时段、检查间隔、复报间隔、弹窗开关、声音开关和开机启动。
- 展示订单列表、店铺状态、检查记录与提醒历史。

### 第一版不包含

- 保存或自动填写店铺账号密码。
- 绕过验证码、二次验证或平台风控。
- 自动处理、审核、发货或修改订单。
- 云端同步、多电脑同步或多人协作。
- 支持 Chrome 以外的浏览器。
- 店小秘页面之外的其他 ERP 或销售平台。

## 系统架构

### Chrome 扩展

复用并扩展现有 `browser-plugin/`。扩展按平台拆分页面适配器：

- `DianxiaomiOrderAdapter`：识别四个店小秘订单列表页面，解析当前店铺、订单号、状态和两个时间字段。
- `AliExpressOrderAdapter`：识别速卖通订单管理页，解析当前店铺、订单号、状态和可用时间字段。
- `ScanCoordinator`：等待页面稳定、处理分页或滚动加载、收集扫描快照并向托盘程序回传。

扩展不负责最终时间判定或提醒节流，只返回规范化的订单数据和扫描状态。这样页面解析变化不会与 Windows 通知逻辑耦合。

### .NET 8 托盘程序

托盘程序使用 WPF 构建，以降低系统托盘、开机启动和单文件发布的复杂度。主要模块：

- `AccountManager`：管理平台、店铺名称、账号标识、Chrome 配置目录、启用状态和登录状态。
- `ScheduleService`：在指定时段按间隔创建检查任务，防止同一账号重入。
- `ChromeProfileLauncher`：为每个账号启动对应 Chrome 登录配置并打开目标页面。
- `NativeMessagingBridge`：通过 Chrome Native Messaging 与扩展双向通信。
- `OrderSnapshotStore`：保存订单快照、扫描批次、提醒状态和检查历史。
- `DeadlineEvaluator`：统一执行临期、紧急和超时判定。
- `AlertService`：负责 Windows 弹窗、声音、稍后提醒、复报节流和点击跳转。

### 本地数据

第一版使用 SQLite。本地保存：

- 店铺配置：平台、店铺名称、账号标识、Chrome 配置目录、启用状态。
- 订单快照：平台、店铺、订单号、原始状态、两个时间字段、来源页面和最后发现时间。
- 扫描批次：开始时间、结束时间、成功或失败、页数、订单数和错误摘要。
- 提醒记录：订单风险等级、首次提醒时间、最近提醒时间、下次允许提醒时间和用户稍后提醒时间。
- 应用设置：监控时段、检查间隔、复报间隔、通知开关、声音开关和开机启动开关。

账号密码不进入 SQLite，也不写入日志。Chrome 登录 Cookie 保存在每个账号独立的 Chrome 配置目录中。

## 唯一键与去重

订单唯一键为：

`平台 + 店铺账号 ID + 订单号`

店小秘四个状态页面中出现的同一订单合并为一条，以最新扫描到的订单状态和页面为准。不同店铺即使订单号相同也不会互相覆盖。

一次完整扫描成功后才提交该店铺的新快照。单页失败或扫描中断时保留上一次成功快照，不把未读到的订单误判为已消失。

## 时间规则

### 考核时间

以本机时区的当天 `19:00` 为基准：

- `0 < 考核时间 - 当天 19:00 < 24 小时`：临期。
- `考核时间 - 当天 19:00 <= 0`：超时。
- 差值不小于 24 小时：正常。

跨越午夜时仍以执行检查当日的 `19:00` 为基准。日期和时间解析失败时不猜测，订单标记为“时间无法识别”，并产生检查异常提示。

### 剩余发货时间

- `0 < 剩余发货时间 < 24 小时`：临期。
- `0 < 剩余发货时间 <= 2 小时`：紧急。
- `剩余发货时间 <= 0`：超时。
- 不小于 24 小时：正常。

订单任一可用时间字段达到更高风险等级时，采用更高等级。页面只显示其中一种时间时，使用可读取到的字段。页面提供绝对截止时间时，扩展先规范化为 ISO 时间；页面提供倒计时时，扩展同时回传原始文本和计算后的秒数。

## 调度与账号流程

### 添加速卖通店铺

1. 用户填写店铺名称和账号标识。
2. 托盘程序创建独立 Chrome 配置目录。
3. 程序使用该配置打开速卖通订单管理页。
4. 用户完成首次登录、验证码或二次验证。
5. 扩展确认订单页可访问后，账号状态变为“在线”。

### 定时检查

1. `ScheduleService` 判断当前时间是否位于监控时段。
2. 对所有已启用账号创建检查任务；同一账号已有任务时跳过本轮，防止重入。
3. Chrome 未运行时自动启动对应配置；已运行时复用窗口或标签页。
4. 扩展依次打开目标页，等待页面稳定并扫描所有页。
5. 扩展回传完整扫描结果；托盘程序验证批次完整性后提交快照。
6. `DeadlineEvaluator` 计算风险等级并生成统计。
7. `AlertService` 根据状态变化和节流记录决定是否弹窗与播放声音。

店小秘账号默认检查四个固定页面；每个速卖通账号检查一个订单管理页面。不同账号可并行调度，但第一版限制并发数量，避免同时启动过多 Chrome 实例。

## 预警规则

以下情况立即提醒：

- 订单首次进入 24 小时临期范围。
- 订单从临期升级为 2 小时内紧急。
- 订单进入超时状态。
- 临期、紧急或超时订单总数增加。
- 账号登录失效、出现验证码、页面无法识别或完整扫描失败。

对仍未处理的风险订单，每 2 小时复报一次。用户点击“稍后提醒”后，以用户选择的时间为准暂停该批提醒；新的订单、风险升级或账号异常不受旧的稍后提醒抑制。

弹窗和声音是独立开关。关闭声音不影响弹窗；关闭弹窗时仍在主面板和托盘图标显示计数。托盘图标按最高风险显示正常、临期、紧急、超时或检查异常状态。

## 界面设计

### 托盘主面板

- 顶部：运行状态、下次检查时间、立即检查按钮。
- 统计卡：24 小时内、2 小时内、已超时、在线店铺数。
- 筛选：平台、店铺、风险等级、订单状态和关键字。
- 订单表：平台、店铺、订单号、状态、考核时间、剩余发货时间、风险、最后检查时间和打开订单操作。
- 导航：订单、店铺账号、提醒设置、检查记录。

### 店铺账号

展示平台、店铺名称、账号标识、登录状态、上次成功检查和最近错误。支持新增、编辑、停用、删除、重新登录和单店立即检查。

### 提醒设置

- 监控开始与结束时间。
- 检查间隔，允许设置 `5–120` 分钟。
- 复报间隔，默认 2 小时。
- Windows 弹窗开关。
- 声音开关与试听。
- 开机启动开关。
- 登录失效提醒开关。

### Windows 弹窗

弹窗显示临期、紧急、超时数量和涉及店铺，提供“查看订单”和“稍后提醒”。点击“查看订单”打开主面板并按本次预警筛选；点击具体订单打开对应账号配置下的来源页面。

## 异常处理

- 登录失效、验证码或二次验证：账号标记为“需要登录”，暂停该账号自动扫描并提示用户处理。
- 网络失败：本轮记录失败并按退避策略重试，不清空上次成功数据。
- 页面结构变化：适配器返回“页面无法识别”，记录有限的诊断信息，不记录敏感页面内容。
- 分页失败或数据不完整：整批扫描失败，不提交部分结果。
- 时间解析失败：订单保留并标记“时间无法识别”，不把猜测值用于预警。
- Native Messaging 断开：扩展和托盘程序均显示离线状态，下轮调度前尝试重连。
- Chrome 启动失败：记录可行动错误，包括 Chrome 不存在、配置目录不可访问或进程启动失败。
- 声音播放失败：仍显示弹窗和面板计数，不阻断扫描。

日志默认不包含 Cookie、账号密码、完整页面 HTML 或订单买家隐私信息。

## 验证策略

### 单元测试

- 考核时间相对当天 19:00 的边界：恰好 24 小时、恰好 0、小于 24 小时和跨午夜。
- 剩余发货时间的 24 小时、2 小时和 0 边界。
- 两类时间字段采用最高风险等级。
- 订单唯一键、四页去重和跨店铺隔离。
- 状态变化立即提醒、2 小时复报和稍后提醒覆盖关系。
- 监控时段跨午夜与非跨午夜判断。

### 集成测试

- 店小秘四页模拟 DOM 的解析、分页、重复订单合并和完整批次提交。
- 速卖通模拟 DOM 的解析、多店铺隔离和登录失效识别。
- 扩展与 Native Messaging 主机通信。
- SQLite 设置、账号、订单、批次和提醒记录持久化。
- Chrome 配置启动、页面打开、任务防重入和失败恢复。

### Windows 验证

- Windows 11 安装、开机启动、托盘图标和单实例运行。
- 弹窗、声音开关、声音试听、稍后提醒和点击跳转。
- Chrome 关闭时自动启动，登录失效时正确提示。
- 至少一个真实店小秘账号和一个真实速卖通店铺完成页面适配验证。

真实页面 DOM 与模拟页面不一致时，以真实登录页面适配通过为最终标准；平台风控、验证码和二次验证只验证人工接管流程，不尝试绕过。

## 验收标准

- 用户可安装 Chrome 扩展和 Windows 托盘程序，并在 Windows 11 上正常开机启动。
- 店小秘账号能够按计划完整检查四个指定页面。
- 用户可添加多个速卖通店铺，每个店铺拥有独立登录会话并可单独检查。
- Chrome 未运行时程序可自动启动对应登录配置；登录失效时给出明确提示。
- 两类时间规则在边界测试中得到一致结果，临期、紧急和超时统计准确。
- 同一店铺的重复订单只统计一次，不同店铺之间互不覆盖。
- 状态变化立即提醒，未处理风险订单按配置复报，弹窗和声音可独立关闭。
- 任一店铺检查失败不会清空其他店铺或上一次成功数据，也不会显示“无临期订单”的误导结果。
- 用户可从预警进入筛选后的订单列表，并打开对应订单来源页面。

## 实施边界与停止条件

实施仅修改或新增与本功能直接相关的 Chrome 扩展、.NET 托盘程序、测试和安装配置，不重构现有 FastAPI 商品上架业务。

若真实页面出现无法通过常规 DOM 读取的数据、强制验证码、平台禁止自动化、账号权限不足或页面字段含义与本设计不同，则停止该平台的真实联调，保留模拟测试结果并向用户报告具体阻塞，不采用绕过平台安全机制的方案。
